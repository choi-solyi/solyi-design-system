# 0.11.0 통합 검수 · 2026-10-23 UTC

문서0.11.0 / Core0.4.3 / Vue UI0.9.0의 기록입니다. 최종 CI와 공개 SHA 확인은 배포 실행 결과로 구분합니다. npm 게시·1.0.0 변경·역사 산출물 삭제·도메인 설정 변경은 하지 않습니다.

## 통과한 자동 검사

- Core/UI build, strict declarations, exports, CSS·폰트·라이선스, 두 개의 깨끗한 tarball 소비 앱 설치, 독립 소비 앱 types/build, 30개 canonical SFC의 types/format/lint/runtime.
- 폼·입력·오버레이·날짜/시간·선택·정렬·페이지·progress·locale·S/V 회귀. SForm과 실제 Vuetify grid 별칭3개를 포함한 공개38개 API의 Props/Slots/Events/Methods를 실제 소스와 대조했습니다.
- Vue preset 실제 import injection, 두 앱의 TypeScript 및 readonly lint globals, ESLint의 잘못된 이름·재할당 거절 사례. Prism의 Vue template/script setup TypeScript/style·interpolation 및 30개 화면/복사/실행 원본 일치, 3테마 light/dark 코드 색 대비.
- HTTP 경로에서 이전0.10.0 → 업데이트0.11.0 → 롤백0.10.0의 실제 설치/types/build, integrity·누락·변조·덮어쓰기 거절. 다른 프로젝트를 업데이트하지 않았습니다.
- 문서105개 목적지와 기존 앵커, 정확한 날짜·시간 별칭 검색, IME·키보드·초점·설정 복원, 저장하지 않은 편집 보호, 현재 권장 설치 쌍만 노출하는 문서 검사.

검사는 통과한 초기 단계의 반복 대신 실패한 단계부터 이어서 실행했습니다. Vite의 큰 chunk 경고는 남아 있으며 성능 통과 판정으로 바꾸지 않습니다.

## 실제 화면과 조작

사용자 PC에 설치된 Google Chrome155.0.8059.85를 Playwright Core1.64.1의 격리 headless 프로필에서 실행했습니다. sandbox를 유지하고 임시 localhost 외부 요청을 차단했습니다. 사용자 브라우저 프로필이나 OS 설정을 사용·변경하지 않았습니다. reduced-motion은 context 에뮬레이션입니다.

1180·720·333 CSSpx의 light/dark에서 메뉴·검색·코드 탭·우측 복사·실제 clipboard·현재 설치 쌍, SForm 오류→ref 초점→성공, 오류 요약 링크를 실행하고 캡처했습니다. 720/333은 touch 에뮬레이션이며 실제 Fold가 아닙니다. 스타터는 mode URL과 html data-mode 단언으로 실제 모드를 확인했습니다.

직접 읽은 이미지는 세 폭의 light/dark 코드, 폼 오류/성공 대표 화면, 333px 양 모드 오류 요약, 333px dark 모바일 메뉴, 1180 light/333 dark 설치 카드 및 수정 후 API 표입니다. API 후속 조작 검사는 세 폭·양 모드에서 통과했습니다. 이는 선택한 상태의 검수이며 모든 조합의 시각 보증은 아닙니다.

로컬 근거는 qa-output/integration-0.11/의 PNG와 report.json·report-api.json·report-forms.json, integration-0.11-pipeline/resume/check/tests/tests-tail/browser/browser-api/browser-forms 및 final 로그입니다. 이미지·로컬 경로·사용자 파일은 게시 산출물에 넣지 않습니다.

## 미검증

실제 Safari, 물리 Fold/터치, 화면 낭독기, 400%·forced colors, 실제 네트워크·CLS 성능은 이번 실행에서 미검증입니다. 자동 대비 검사와 키보드 검사를 접근성 준수 인증으로 표현하지 않습니다. 최종 공개 CI·자산 해시는 이 문서 작성 뒤 배포 실행과 최종 보고에서 확인합니다.
