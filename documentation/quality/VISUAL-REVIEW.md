# 패키지 데모 시각 검토

> 문서 v0.3.0을 기준으로 수행한 과거 검토입니다. 당시 다이얼로그 반경 28px, 패키지 버전, 캡처 제한 등의 수치와 상태는 이력이며 현재 사양이 아닙니다. 이 기록은 치수·동작 확인을 스크린샷 검수 완료로 표현하지 않습니다.

기준: v0.3.0 / 3bbac067. 범위는 이 저장소의 /starter/, 공유 패키지 스타일과 대응 문서입니다. 타이포·색상·버튼 반경 6px·조밀한 데이터 행과 모든 상호작용을 유지합니다.

## 계획

1. [x] 체크아웃과 기존 배포 성공을 확인하고, 오래된 초기 CI 기록을 재실행하지 않고 보존합니다.
2. [x] 소스 원인과 우선순위별 발견을 기록하고 패키지 예제를 프레임워크 독립 예제와 비교합니다.
3. [x] 공유·패키지 원인과 데모 조합을 수정하고 두 독립 소비 프로젝트에 갱신한 tarball을 설치합니다.
4. [ ] 1644/766/333 CSSpx·3개 테마×라이트/다크의 실제 Chrome 렌더링·치수·키보드 검사는 마쳤으나 **캡처 시간 초과로 스크린샷 기반 시각 검토는 미검증**입니다.
5. [x] 패키지·export·타입·소비 앱·DOM·대비 회귀와 관련 레이아웃 검사를 실행합니다.
6. [ ] 준비되면 한 번에 커밋·푸시하고 기존 Pages workflow를 기다린 뒤 공개 파일과 실제 공개 UI를 확인합니다.

설치된 0.1.0을 실제 Chrome 1643 CSSpx에서 측정한 기준값: caption 텍스트는 내부 테두리에서 1.11px, 제어→표 간격은 약 0px, 정렬 라벨 시작은 본문보다 오른쪽으로 13.10px였습니다. 네 페이지 버튼은 이미 약 35.99px의 같은 상자였고 결함은 버튼 크기 차이가 아닌 내부 문자 위치였습니다.

캡처 환경: 연결된 Chrome만 도구에 노출되었습니다. 문서화된 두 캡처 경로 모두 정상 로컬 페이지의 HTTP 접근 복구 후에도 Page.captureScreenshot 시간 초과(5초)가 났습니다. native·다른 브라우저 제어나 보안 우회는 사용하지 않았습니다. 최초 로컬 서버의 sandbox 네트워크 격리는 승인된 임시 loopback 미리보기 서버로 교정하여 탐색을 복구했습니다. 실제 이미지를 얻기 전까지 스크린샷 검토는 미검증입니다.

## 검토 범위

- 패키지 Button·Field·Dialog·Table의 기본·hover·focus·disabled·loading·error·empty·selected, 제목·도움말 기준선, 카드·필드 간격, 초점 잘림, 안정적인 표 너비와 전체 텍스트 접근.
- 대응 Core 참고 예제의 검색·필터·선택·페이지 이동, 오류 요약, 404 복구, 시간 팝오버, 자동완성, 진행률과 오버레이 초점.
- 대표 샘플의 데스크톱·중간 폭·332–333 CSSpx, 라이트·다크와 3개 브랜드 테마.
- 시각 검수 완료에는 실제 스크린샷이 필요합니다. DOM 치수나 기능 검사 통과만으로 시각적 완성도를 입증하지 않습니다. 캡처가 불가하면 제한을 기록하고 독립적으로 완료한 작업은 보존합니다.

## 게시 전 확인 결과

- Caption padding은 block 16px / inline 12px이고, 테두리를 포함한 텍스트 상자 여백은 약 13.11px입니다. 제어→표 간격은 약 15.99px이며 header·body 시작 차이는 기존 약 13.10px에서 약 1.11px로 바뀌었습니다.
- 페이지 이동 버튼은 데스크톱 약 35.99px·좁은 화면 약 43.99px를 유지하고 SVG와 버튼 중심 차이는 가로·세로 각각 0.02px 미만입니다. 실제 chevron path는 문서의 기존 UI 아이콘 원본을 import합니다.
- 데스크톱 데이터 행은 약 49.08px를 유지합니다. 766px에서 기본·정렬·2페이지·빈 필터 전후 열 너비는 정확히 47.986 / 305.625 / 95.990 / 127.986 / 71.997px로 동일했습니다(변화 0px).
- 실제 18개 폭·테마·모드 조합(1644/766/333px × violet/sage/sand × 라이트/다크)에서 페이지 가로 넘침이 없었습니다. 버튼 반경 6px, Field 바깥 반경 10px, 데스크톱 제어 높이 36/40px와 좁은 화면 44px를 유지합니다. 모바일 caption을 표시하고 데스크톱 표를 카드로 전환합니다.
- Field 라벨·제어 간격은 약 8px, Dialog 문단 간격은 약 12px이며 당시 반경은 28px, 좁은 화면 닫기 행동의 안쪽 여백은 약 17px입니다. 실제 Chrome Escape로 실행 버튼에 초점을 복귀했습니다. native Tab·Enter·Escape로 잘리지 않는 툴팁·전체 제목 Dialog·초점 복귀를 확인했습니다. 툴팁은 잘리는 표 경계 밖의 body에 붙입니다.
- 오류·재시도 후 선택 ID 3개를 보존하고 오류 중 페이지 이동을 비활성화한 뒤 복구했습니다. 빈 필터는 1페이지로 돌아갑니다. 독립 소비 앱의 실제 폰트 family·caption padding·SVG·Dialog 간격은 starter adapter 없이 기존 토큰 값과 일치합니다.
- 실제 Chrome에서 Core 참고 Field(40px·반경 10px), Textarea(약 96px·필요할 때만 스크롤), 시간 패널(padding 16px·Escape 복귀), 알 수 없는 진행률(aria-valuenow·가짜 퍼센트 없음), 연결된 오류 요약, 404 경로 보존과 자동완성 키보드 선택을 확인했습니다. 766px에서 참고 검색·필터는 모두 높이 40px·같은 시작점이며 333px에서는 의도적으로 세로 배치하고 44px를 유지합니다.
- 전체 로컬 pipeline 통과: 실제 tarball 소비 앱 2개, exports·타입·CSS·공유 아이콘, 소스 직접 연결 없음, 컴포넌트 런타임, 기존 복구·날짜·업로드·탐색·진행률 검사, 토큰 대비 186쌍과 버튼 상태 대비 672개(최소 4.562:1).
- 소비 연결 검사가 lock 갱신 중 임시로 생긴 저장소 소스 의존성을 발견하여 게시 전에 제거했습니다. 런타임 file 의존성을 명시적으로 거부합니다. 갱신은 자체 패키지 lock 2개만 다시 해석한 뒤 깨끗한 npm ci를 사용하여 제삼자 버전 고정을 보존합니다. 깨끗한 설치 전 Windows 미리보기 프로세스의 파일 잠금을 해제했으며 권한을 변경하지 않았습니다.

이 파일은 게시 전 검토의 이력입니다. 커밋·CI·공개 HTTP/SHA 결과는 기록만을 위한 추가 배포 대신 최종 릴리스 보고에 남깁니다. 당시 스크린샷 제한은 미해결이며 위 치수 검사를 성공한 이미지 검토로 표현하지 않습니다.
