## 실제 패키지

- 저장소 밖에 npm/pnpm × 신규/기존 Vue 앱 네 개를 생성했습니다. workspace 링크와 소스 alias 없이 새 tarball만 설치했습니다.
- 네 앱 모두 전역 등록, 자동 import, 문서 설정 그대로 타입 검사·lint·프로덕션 빌드, 브라우저 폼 입력·오류·제출·재설정을 통과했습니다. Vue 인스턴스는 각각 하나입니다.
- TypeScript 5.9.3, 자체 공개 선언 25개를 skipLibCheck:false로 검사하여 자체 진단 0건을 확인했습니다. 외부 의존성 선언 진단 769건은 별도입니다. 소비 앱의 skipLibCheck:true는 외부 선언 정책이며 전체 외부 선언 엄격 검사 통과를 뜻하지 않습니다.
- solyi-ui-0.11.1.tgz: 54개 파일, 3,589,668 bytes. SHA-256: d12c7b7cbe32db1ba0878e3b94c8de6007dbef46951ad323a400c48a85cb7137.
- exports 대상 19개, CSS·토큰·폰트·원문 라이선스, 비밀 패턴 0건과 별도 Core 설치 불필요를 검사했습니다.
- 기존 tarball과 CI 권한 파일 65개가 최초 검수 SHA와 동일합니다. pack은 기존 파일과 다른 바이트를 덮어쓰지 않습니다.

344×882, 882×344, 690×829, 829×690의 대표 영향 화면을 검사했습니다.

차트·입력 조합·테마·설치·코드·알림의 30개 캡처를 직접 판독했고 29개를 시각 근거로

기본 영향 18개 화면에서 페이지 오류와 가로 넘침은 0건입니다. 실제 Fold 실기기,
Safari/iPhone, 화면 낭독기 검증을 대신하지 않습니다.

문서/컴포넌트 런타임, 실제 30개 Vue SFC의 타입·자동 import·lint·포맷·소스 일치,
API 생성, 설치 업데이트/롤백, 토큰 대비, 라이선스·공개 파일 목록 검사를 통과했습니다.
전체 재검사 대신 이미 확보한 감사 범위를 유지하고 바뀐 동작과 화면을 재검증했습니다.

axe-core 4.14.0으로 테마·표·일괄 재시도·숫자 입력 네 경로를 재검사했습니다.
표 페이지 번호의 가시 숫자 1/2와 접근 가능한 이름의 `1페이지`/`2페이지`를
서로 다른 단어 토큰으로 보는 자동 검사 경고 2건은 수동 검토에서 숫자 포함을 확인했습니다.
이 사례는 실제 라벨 누락과 구분합니다. 색 대비 등 incomplete 결과는 자동 통과로
계산하지 않으며, 모든 상태의 화면 낭독기·음성 제어 검증을 뜻하지 않습니다.

## 성능 및 남은 한계

Lighthouse 13.5.0 모바일 설정으로 로컬 수정본의 두 경로를 각 3회 측정했습니다.
로컬 서버는 공개 CDN과 압축·네트워크 조건이 다르므로 이전 공개 점수와 직접 비교하지
않습니다. 공개 반영 후 같은 URL/설정의 측정 결과를 배포 보고에서 구분합니다.
선택적 폰트 대기는 없어졌지만 전체 UI 폰트 크기와 스타터 JS 초기 비용은 남아 있습니다.
Lighthouse/axe의 자동 점수는 WCAG 인증이나 실제 사용자 Core Web Vitals 결과가 아닙니다.

npm 레지스트리 설치, dist-tag, 게시 권한/2FA, 실제 Safari·Fold·화면 낭독기와 모든 상태의
테마 조합은 별도 확인 대상입니다. 패키지의 private 게시 방지 설정은 유지합니다.
